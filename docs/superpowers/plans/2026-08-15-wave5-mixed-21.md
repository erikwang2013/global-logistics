## 代理工作说明书（下文每个代理任务全文引用，自包含）

### 适配器契约（每承运商一个文件 `src/Carriers/{Domestic|International}/{Class}.php`）

- `final class {Class} implements CarrierInterface`，命名空间按通道（`GlobalLogistics\Carriers\Domestic` 或 `...\International`）
- readonly 提升构造器：`public function __construct(private readonly Config $config, private readonly ClientInterface $http) {}`；OAuth2 承运商（如无）在构造器内用 `OAuthTokenClient` 包装
- `private const ENDPOINT = '官方接口 URL'`；请求地址 `$this->config->get('{slug}.endpoint', self::ENDPOINT)` 支持覆盖
- 认证密钥一律 `$this->config->get('{slug}.xxx')` 读取（键名按各承运商实际文档），零硬编码
- `private const STATUS_MAP = ['关键词' => TrackStatus::X, ...]`：关键词小写，`|` 分隔同义（如 `'delivered|signed|success' => TrackStatus::DELIVERED`）
- 私有方法 `mapEvent(array $raw): TrackingEvent`、`mapStatus(string $raw): TrackStatus`（查 STATUS_MAP，未命中 → `TrackStatus::UNKNOWN`）、`parseTime(string|null $raw): ?DateTimeImmutable`（容错多格式）
- 事件必须升序：解析后若首事件时间 > 尾事件时间（降序），整体反转（参照 InPost.php 的 `ensureAscending` 模式）
- `deliveredAt` 仅当最新事件状态为 `TrackStatus::DELIVERED` 时设置，否则 `null`
- 错误契约（消息精确匹配，`XX` 为大写承运商代码）：
  - HTTP 401/403 → `throw new AuthException('[XX 401] 认证失败')`
  - HTTP >= 400 → `throw new LogisticsException("[XX {httpCode}] 接口错误")`
  - JSON/XML 解析失败或结构不符合预期 → `throw new LogisticsException('[XX] 响应解析失败')`
  - 响应无任何事件 → `throw new TrackingNotFoundException($trackingNo)`
  - `createOrder`/`createLabel`/`subscribe` → `throw new LogisticsException('{code} xxx 待实现')`（code 全小写）
- docblock：`* VERIFIED-REQUIRED：` 注明需要真实验证的点 + 官方文档 URL 来源
- XML 响应的承运商参照 `src/Carriers/International/CanadaPost.php` 的 SimpleXML 用法；国内 EDI 签名类参照 `src/Carriers/Domestic/Uc.php`

### 测试契约（每承运商一个文件 `tests/Carriers/{Class}Test.php`，7 个用例）

fixtures 放 `tests/fixtures/{slug}/`：`track.json`（或 `.xml`，成功响应含真实样本单号）、`empty.json`（无事件）、`error.json`（业务错误）；mock 用 `tests/Support/FakeHttpClient.php` 的 `$http->handler` 回调返回 `GuzzleHttp\Psr7\Response`。参照 `tests/Carriers/InPostTest.php`：

1. `testQueryTrackParses` — happy path：断言请求方法（GET）、完整 URL（含单号）、认证请求头；断言返回 `Tracking` 的 carrierCode/trackingNo/status/events 数量与内容/latestDescription/rawStatus/deliveredAt（已签收时）
2. `testDescendingTracesAreReversed` — handler 内联返回降序事件，断言反转后升序 + deliveredAt 正确
3. `testEmptyTracesThrowsTrackingNotFoundException` — `empty` fixture → `TrackingNotFoundException`
4. `testBusinessErrorThrowsLogisticsException` — `error` fixture + 400 → 断言消息含 `[XX 400] 接口错误`；若承运商业务错误以 200 + 错误码返回，改为 200 fixture 并断言 `[XX] 响应解析失败` 或业务错误消息
5. `testAuthFailuresThrowAuthException` — 401 响应 → `AuthException`，消息含 `[XX 401] 认证失败`
6. `testNonArrayBodyThrowsLogisticsException` — 非法 JSON（如 `'"boom"'`）或非法 XML → `LogisticsException` 消息含 `响应解析失败`
7. `testUnimplementedMethodsThrow` — `createOrder(new OrderRequest([], []))`/`createLabel(new Order('单号'))`/`subscribe('https://example.com/callback')` 各断言消息为 `'{code} xxx 待实现'`
